## 1. Auth
- Login screen: app/login/page.tsx (527 lines). Rendered by ConditionalApp whenever not authenticated (app/components/ConditionalApp.tsx:36-38); no separate /login redirect and no middleware.ts / proxy.ts exists (searched project root and app/). Email + password form, Google Sign-In (GIS script), forgot-password modal (POST same-origin /api/forgot-password, login/page.tsx:405; proxies a Laravel form controller, app/api/forgot-password/route.ts:6-14).
- Login call: AuthContext.tsx:221-239 `POST {API_BASE_URL}/api/api-login` JSON `{email,password,type:'API'}`, called directly from browser (not proxied). Success = res.ok. Error text = data.message.
- Google: AuthContext.tsx:246-267 POST /api/google-auth (Next route) -> Laravel `POST /api/google-auth` body `{id_token, credential, type:'API'}` returns same shape as api-login (app/api/google-auth/route.ts:12-17).
- Mobile handoff: AuthContext.tsx:278-304 `GET {API_BASE_URL}/api/mobile/web-handoff/claims?ticket=` ; success when `data.status==1`; optional `redirect_path`. Page: app/mobile-bridge/page.tsx.
- Token storage: localStorage only, no cookie. persistLoginPayload (AuthContext.tsx:171-219) writes keys:
  - `auth` = {name,email,avatar}
  - `menuContext` = {sub_institute_id,user_id,user_profile_name,user_profile_id,client_id}
  - `userData` = whole login payload (includes `user_token`/`token`, `host_name`, `logo`, `is_admin`, `academicTerms`, `academicYears`, etc.)
  - `sessionDate` = YYYY-MM-DD
  - others read: `selectedAcademicYear`, `selectedAcademicTerm`, `sub_institute_id`, `term_id`, `syear`, `appBuildId`.
  Login payload field names accepted are listed at AuthContext.tsx:178-187 (data may be wrapped in `data.data`). Logo URL rebuilt as `${host_name}/admin_dep/images/${logo}` (:206-208).
- Token read: lib/erp-client.ts:58-177 buildSessionContext() merges userData + menuContext + sessionData; token = first non-empty of `user_token`, `token` (:143-145). Returns {baseUrl (override || userData.host_name || API_BASE_URL), token, subInstituteId, syear, userId, termId, isAdmin}.
- Token sent: `Authorization: Bearer <token>` + `Accept: application/json` (erp-client.ts:179-188 createAuthHeaders). installErpAuthFetch() (erp-client.ts:218-256, installed at module scope in ConditionalApp.tsx:10) monkey-patches window.fetch to add the Bearer header to any request to the ERP origin that lacks Authorization (needed because Laravel config/api_guard.php now refuses anonymous api/*). Dashboard proxies instead send `x-laravel-token`, `x-laravel-base-url`, `x-sub-institute-id`, `x-academic-year-id`, `x-user-id`, `x-term-id` headers to Next routes (app/dashboard/_lib/dashboard-api.ts:9-19).
- Common request params (the "legacy controller" convention): query/body `type=API` (or `JSON` for admin dashboard), `sub_institute_id`, `syear`, `user_id`, optional `term_id` (erp-client.ts:190-203; erp-legacy.ts:99-118). `type=API` is what flips Laravel's `is_mobile()` from Blade to JSON (erp-legacy.ts:20-26 comment). Mobile should copy this.
- Tenant: `sub_institute_id` from login payload; no tenant switcher in the web client found.
- Role derivation: free-text `user_profile_name` (+ numeric `user_profile_id`) from the login payload, stored in menuContext. No role enum from server. Some code also uses `is_admin` (1 or 2) and profile id 1 (DashboardShell.tsx:65-87 isBrainVisibleByLmsSession). Student check is by name because `user_profile_id` for Student differs per tenant (DashboardShell.tsx:92-108).
- Session lifetime: 30 min inactivity timer on mouse/key/click/scroll/touch (AuthContext.tsx:42,99-130) and forced logout when calendar date changes, checked each 60 s (:132-155). Both silently clear the 3 keys, no server call.
- 401 handling: NO global interceptor / 401 redirect found (searched for 401 across app/lib/components/hooks/contexts: only isolated checks in app/general/onboarding/_lib/onboarding-api.ts:206,607 and app/hrit/_lib/payroll-api.ts). Errors surface per screen via thrown Error messages. Mobile should add its own central 401 -> logout.
- Logout: AuthContext.tsx:319-334 clears state, calls purgeClientState() (lib/app-version.ts: clears storage, caches, cookies, service workers, :104-118) then `window.location.replace('/')`. No server logout/revoke call.
- Build-id cache purge: lib/app-version.ts + next.config.ts:15-44 (NEXT_PUBLIC_APP_BUILD_ID = git sha); AuthContext.tsx:167-169 syncAppBuild on every load.
- Server proxies: app/api/proxy/route.ts (GET/POST/PUT/PATCH/DELETE, `?path=` relay to `${API_BASE_URL}/<path>`, forwards Authorization/Cookie; path mapping for proxy_master -> school_setup/, :6-19) and app/api/proxy-file/route.ts (multipart POST relay). Guards: lib/security/request-guards.ts (isSafeRelayPath, body size), lib/security/trusted-backend.ts (client-supplied base URL honoured only if on allow-list). These exist only for CORS/secrecy; mobile can call Laravel directly.

## 4. Data fetching, errors, pagination, selectors
- Plain `fetch` + useState/useEffect + AbortController everywhere (e.g. useMenuRights.ts:96-163, dashboard-api.ts). No SWR/React Query. Custom hooks per module (app/hrit/_lib/use-payroll.ts etc.).
- Two main transports:
  1. legacyRequest(path,{query,body,method:'GET'|'POST'}) (lib/erp-legacy.ts:158-189): fetches `/api/proxy?path=<laravel path>&type=API&sub_institute_id&syear&user_id[&term_id]...`, Bearer header; on !ok throws failureFrom() which unwraps Laravel `{errors:{field:[msg]}}` then `message` then "Request failed (status)" (:139-156); status in body `'0'` or `'2'` => failure (JWT guards use 2) unless tolerateStatusZero (adminapi returns status 0 "No Record" for empty) (:183-187). Envelope is FLAT (payload keys next to status/message). Arrays may come as arrays or id-keyed objects (recordArray :33-37). `name[]` repeated keys for array params (:81-92). Writes use `contextBody()`; `bareBody` skips context fields (:109-137).
  2. Direct domain services (components/domain/**) calling `${session.baseUrl}/api/...` with createAuthHeaders (see section 5).
- ApiEnvelope: `{status|status_code, message, data}` (erp-client.ts:13-18); success is status "1".
- Errors/toasts: no toast library. Errors are shown inline with ErpAlert (26 files) / DashboardError with Retry (app/dashboard/_components/DashboardPrimitives.tsx) / EmptyState; a few `alert(` calls (8 files). components/document-template uses its own toast. Messages follow the design-system tone (what happened + what to do).
- Pagination/search: mostly CLIENT-SIDE (RecordTable sorts/slices whole result: RecordTable.tsx:105-126). No standard server page/per_page contract found in shared code; module-specific.
- Academic-year selector: single global selector in Header (app/components/Header.tsx:325-395). Years/terms from login payload `academicYears` / `academicTerms` (table academic_year: one row per institute/syear/term; keys `syear`, `title`, `sort_order`) and refreshed via `GET {API_BASE_URL}/api/academic-terms?type=API&sub_institute_id&syear` (AuthContext.tsx:343-365). Selected year stored in localStorage `selectedAcademicYear` (integer syear; normalizeAcademicYear strips "2024-2025" to first 4 digits, erp-client.ts:29-35), term in `selectedAcademicTerm`; changes published via lib/academic-year.ts (event `lms:academic-year-change`, :1-40). Default active year = syear of the first academicTerms row (the term covering today), NOT academicYears[0] (erp-client.ts:102-136). syear + term_id are sent on nearly every API call.
- Standard/division selector: `loadClassOptions()` (lib/class-options.ts:60-) calls `GET api/class-teachers` (via legacyRequest) returning `academic_sections`, `standards` (with grade_id), `divisions` (with standard_id). Chained Grade(academic section) > Standard > Division dropdowns with child reset (components/erp/ClassFilters.tsx:25-100). Helper fns standardsForGrade / divisionsForStandard. Teacher-scoping is server-side for teacher endpoints.
