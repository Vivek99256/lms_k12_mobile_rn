# Student mobile tiles - backend audit (read-only, no DB)

All paths relative to D:/next_lms_erp. `jwt()` = `$this->jwtToken()->validate()` (generationtux/jwt-artisan; token from `Authorization: Bearer` header, or body/query input named `token` unless JWT_HEADER_ONLY - vendor/generationtux/jwt-artisan/src/GetsJwtToken.php:21-40). Missing token throws NoTokenException, caught by the controller `catch (\Exception)` -> 401.

## Global facts
- Route registration: RouteServiceProvider::map() (app/Providers/RouteServiceProvider.php:50-120). student.php, cal.php, consent.php, fees.php, lms.php, result.php, web.php are mounted with the `web` group (RouteServiceProvider.php:292-297, 327-332, 341-346, 355-360, 383-388, 260-265). adminapi.php is mounted with NO middleware group at all (RouteServiceProvider.php:396-400) -> no session, no CSRF, no throttle.
- `web` group (app/Http/Kernel.php:33-45) includes `api.jwt` (RequireApiJwt) but it only acts on paths starting `api/` (RequireApiJwt.php:~115 apiPath) -> NO effect on any endpoint below (none lives under /api).
- CSRF: VerifyCsrfToken $except = circular/*, api/*, fees/*, https://erp.triz.co.in/*, https://dev.triz.co.in/*, http://127.0.0.1:8000/* (app/Http/Middleware/VerifyCsrfToken.php:19-25). So all POSTs work on erp.triz.co.in; on http://localhost:8000 or LAN IPs the web-group POSTs (not circular/*, fees/*) get 419. adminapi.php endpoints are outside the web group -> no CSRF anywhere.
- Common pattern ("PATTERN A"): controller does only jwt() (401 `{status:'2',message,data:[]}` on fail), then reads student_id / sub_institute_id / syear from request body. No check that body ids match token payload -> any valid token (any school/role) can read any student (IDOR). Responses are `json_encode($res)` (Content-Type text/html, HTTP 200 even for "Parameter Missing"). No Laravel validator unless noted.
- api-login (app/Http/Controllers/api/ApiLoginController.php): route routes/api.php:95 `POST /api/api-login` (throttle 20/min). Body email,password,type(default API; unused for payload). Student branch: tblstudent by email+status=1 (:46-64); payload = {id: tblstudent.id, sub_institute_id, is_admin:"" , client_id:"", user_profile_id, is_student:true} (:413-420, exp only if JWT_TTL_MINUTES>0 :424-428). Response `data.id` = same tblstudent.id (:442). So the endpoints' `student_id` == api-login `data.id`; `sub_institute_id` == `data.sub_institute_id`; syear is NOT in the token (use `data.mobile_syear` = school_setup.syear :435 / academicYears). Any token from api-login passes jwt() on every endpoint below (same secret).
- No endpoint here uses `api.session`/`session` middleware except fees/PaidUnpaid. `type=API` branching: only SessionMiddleware (fees) and the 3 "optional jwt" endpoints noted.
- Schema drift: no query below touches `tblstudent.roll_no`. Only `se.roll_no` (tblstudent_enrollment) in get_wrtreportAPI (adminapiController.php:460/2327, and `$student_data['roll_no']` :2408); fees PaidUnpaid uses `s.*` (fine).
- Route-collision note: `POST /studentSubjectAPI` is declared twice (routes/student.php:237 -> studentHomeworkController, routes/lms.php:359 -> lms_apiController). Laravel keeps the LATER registration (RouteCollection::addToCollections overwrites `$this->routes[$method][$uri]`, vendor/laravel/framework/.../RouteCollection.php:59-69) and mapStudentRoutes runs before maplmsRoutes (RouteServiceProvider.php:50-120) -> lms_apiController wins (no bootstrap/cache/routes*.php exists). The shadowed studentHomeworkController::studentSubjectAPI (studentHomeworkController.php:601) would 500 (`$join->where('s.subject_id = t.subject_id')`).

## Caveats (short)
1. Authorization is only "any valid token". student_id/sub_institute_id/syear are caller-supplied everywhere (cross-student / cross-school reads). Exceptions: fees (school from token via session; student_id still body).
2. Three endpoints skip auth unless `type=API` is sent: studentResultPDFAPI, studentLeaveApplicationAPI, studentParentcommunicationListAPI. The app should always send `type=API`.
3. Two are unusable with token-only calls: `document_details` (GET + session school) and `studentHostelAllocationAPI` (session school). Both need server fixes before being wired to the student menu.
4. Hidden required params vs DB-listed params: circular/fetchData needs `action`; photo/video gallery needs `action`; home_work needs `action`; schoolDetailAPI needs `action` (no student ids); notificationHubAPI needs non-empty `mobile_no`; add_communicationAPI needs `type`; add_leave needs `title`; studentResultPDFAPI needs `term_id`; fees needs `type=API`.
5. Response envelope inconsistent: most `status`; studentCertificate/HW/Infirmary/Vaccination/consent/hostel/parentCommunicationList use `status_code`; document_details returns a bare list; auth failures are `{status:'2'}` (HTTP 401, except fees & wrt which return HTTP 200). Validator failures at studentResultPDFAPI/capture photos return `{response:...}` w/o status; wrt returns status '1' on validation failure. Client must treat `status` OR `status_code` == 1.
6. Content type is text/html for json_encode() responses (except type=JSON on certificate/timetable) - client must JSON.parse the body regardless of header.
7. `data` shape variants: object keyed by id (social_collabrative), by album title (photo/video), keys "1","2","3" (leaderboard, [] when empty), single object (wrt, result Regular PDF) vs lists elsewhere. Empty-set behaviour varies: some return status 1 + [] ; homework & gallery return status 0.
8. Heavy/side-effect calls: studentResultPDFAPI and get_wrtreportAPI generate PDFs synchronously and delete other PDFs in the shared output folder (concurrent users clobber each other). fees PaidUnpaid also needs a current academic_year row (422 otherwise).
9. Raw SQL string concatenation (SQL injection) in studentResultPDFAPI and notificationHubAPI.
10. URL building uses $_SERVER['SERVER_NAME'] (https assumed) - behind proxies/localhost file URLs may be wrong; lms_subject display_image lacks "/" separator.
11. circular/fetchData crashes (500, non-JSON) for a student with no enrollment in the syear.
12. No tblstudent.roll_no usage found in any of these queries (searched all methods above). Only se.roll_no (enrollment table) in get_wrtreportAPI.
13. /api/mobile/bootstrap and MobileBootstrapApiController (new, untracked) were not part of this audit.
